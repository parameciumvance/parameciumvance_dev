# 測試策略

> 狀態：初版整理。來源：[舊專案 SOP](../../開發/專案SOP)、[舊測試筆記](../../開發/測試)。

## 測試層級

| 層級 | 主要問題 | 例子 |
| --- | --- | --- |
| 單元測試 | 單一邏輯單元在可控條件下是否正確？ | 輸入命令後產生預期的控制資料 |
| 整合測試 | 模組／介面接合後是否正確？ | Modbus 收發與控制層串接 |
| 系統／端到端測試 | 完整系統是否滿足外部可觀察需求？ | 收到停止命令後，外部設備收到正確停止訊號 |
| 故障與恢復測試 | 異常、重啟、斷線後是否能恢復？ | 程式非正常結束後重新啟動 |

層級依測試邊界與驗證目標區分，不單純依測試工具或函式名稱判斷。

## 設計原則

1. 先明確描述可觀察的預期行為與失敗條件。
2. 測試正常路徑、邊界值、例外條件與恢復情境。
3. Mock 適合隔離外部依賴，但不能取代必要的真實介面整合測試。
4. Bug 修復應盡量加入能重現問題的回歸測試。
5. 硬體、網路或背景服務相關系統應涵蓋斷線、重啟、逾時、資源占用及非正常關閉。

## 範例：停止命令

- 單元：控制邏輯收到 stop 時，產生停止意圖或呼叫對應介面。
- 整合：通訊模組將停止意圖編碼成符合協定的訊號。
- 系統：完整流程收到 stop 後，外部可觀察到符合需求的停止結果。
- 例外：在明確禁止停止訊號的狀態下，驗證系統遵循已定義規則。
